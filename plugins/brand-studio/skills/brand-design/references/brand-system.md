# From brand strategy to interface

A brand identity is a repeatable relationship between promise, language, visual recognition and behavior. A palette alone is not a brand.

## Discover and define

Identify the audience's situation, the useful change the product provides, competitors' visual conventions, actual reasons to believe, and the primary action. Separate confirmed facts from assumptions. Write one positioning sentence and three voice traits, each with an example of language to use and avoid.

The Design Council's discovery/definition/development/delivery model is a useful process reference: [Double Diamond](https://www.designcouncil.org.uk/resources/the-double-diamond/). It does not prescribe a website layout.

## Develop a direction

Compare two coherent routes against the brief. Describe typography, composition, image production, color roles, shape, motion character and why the audience would recognize the brand. Select a signature device that belongs to the subject: a crop, framing approach, silhouette, material or transition. Do not stack unrelated effects.

Turn the selected route into semantic tokens, asset rules and component behavior. Separate invariants (identity, primary action labels, type families, material/lighting vocabulary) from allowed variation (shot distance, arrangement, section rhythm). Consistency does not require identical sections.

## Preserve the system

Version the brand contract. When the user changes direction, update the contract first, then trace changes to components, assets and copy. Name exceptions and reasons. Reuse the same tokens across marketing and product UI but reduce motion and increase information density where tasks demand it.

Taste references help spot habitual defaults; they are not a universal ban on a font, color or layout. Existing brand evidence outranks fashion. Avoid arbitrary novelty and generic perfection. Never fabricate testimonials, customer logos, origin stories or performance evidence.

[Design Tokens Community Group](https://www.designtokens.org/) provides an interchange standard. Our compact v1 contract is deliberately a project format, not a claim of DTCG schema compliance.
